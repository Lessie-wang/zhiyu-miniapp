## 🔀 集成顺序

### 阶段1: 独立分支并行工作（0-3小时）

**同时进行**：
1. **分支1** - Index 页面修缮
2. **分支2** - Chat 页面修复
3. **分支3** - Knowledge 页面优化

**注意事项**：
- 三个分支完全独立，可以同时进行
- 每个分支只修改各自负责的文件
- 不要跨分支修改文件

### 阶段2: UI设计系统统一（3-4.5小时）

**等待前3个分支完成后**：
4. **分支4** - UI设计系统统一

   - 提取共同样式到全局
   - 创建设计规范文档
   - 提供迁移建议

**注意事项**：
- 分支4必须等待前3个分支完成
- 分支4不修改页面样式，只提取全局样式
- 分支4提供迁移建议，但不强制迁移

### 阶段3: 集成测试（4.5-5小时）

**所有分支完成后**：
1. 合并所有分支到 `dev` 分支
2. 运行完整测试
3. 验证视觉一致性
4. 修复集成问题（如果有）

## ⚠️ 潜在冲突点

### 冲突点1: app.json 页面配置
- **原因**: 多个分支可能修改页面配置
- **涉及分支**: 分支1、2、3
- **解决方案**: 
  - 各分支只修改各自页面的配置
  - 如果需要修改全局配置，在完成报告中注明
  - 集成时手动合并 `app.json`

### 冲突点2: 共享工具函数
- **原因**: 多个分支可能使用相同的工具函数
- **涉及分支**: 分支2（AI工具）、分支3（可能）
- **解决方案**:
  - 不修改工具函数接口
  - 如果必须修改，在完成报告中详细说明
  - 集成时检查工具函数的兼容性

### 冲突点3: 全局样式
- **原因**: 分支4提取全局样式可能与页面样式冲突
- **涉及分支**: 分支4 vs 分支1、2、3
- **解决方案**:
  - 分支4只添加全局样式，不修改页面样式
  - 分支4提供迁移建议，由各分支自行决定是否迁移
  - 确保向后兼容，不破坏现有样式

### 冲突点4: 图片资源
- **原因**: 多个分支可能添加图片资源
- **涉及分支**: 分支1、2、3
- **解决方案**:
  - 各分支使用独立的图片目录
    - 分支1: `assets/images/index/`
    - 分支2: `assets/images/chat/`
    - 分支3: `assets/images/knowledge/`
  - 避免文件名冲突

## 🔙 回滚方案

### 如果集成失败

**步骤1: 识别问题**
1. 检查 console 错误
2. 识别冲突的文件
3. 确定问题来源（哪个分支）

**步骤2: 回滚到集成前**
```bash
# 回滚到集成前的 commit
git reset --hard <commit-hash>

# 或者回滚到 dev 分支的上一个状态
git reset --hard HEAD~1
```

**步骤3: 分析问题**
1. 查看冲突的文件
2. 分析冲突原因
3. 确定解决方案

**步骤4: 修复问题**
1. 修复冲突的代码
2. 重新测试
3. 再次集成

**步骤5: 如果无法修复**
1. 暂时移除有问题的分支
2. 先集成其他分支
3. 单独修复有问题的分支
4. 最后再集成
